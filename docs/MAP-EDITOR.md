# 地图编辑器（`editor.html`）

一句话：**城市版那张图的数据现在是一张 JSON，编辑器就是它的可视化读写器**。
改落点、改路网、改广场半径、改路面起伏、批量改建筑外观 → 存盘 → 刷新游戏，不动一行 JS。

- 数据真源：[`data/town-plan.json`](../data/town-plan.json)（17,206 字节：147 个物件 + 37 棵森林树 + 6 条路（3 条折线、6 条都带纵向起伏）+ 台地 3 块 + 梯道/坡道 2 条）
- 运行时出口：[`src/world/layout.js`](../src/world/layout.js)（薄壳，导出名与迁移前逐字一致）
- 编辑器代码：[`src/editor/`](../src/editor/)（`app.js` 主控 + `state.js`/`view2d.js`/`view3d.js`/`kinds.js`/`problems.js`/`batch.js`）
- 与编辑器共用的**同一把尺**：[`src/map/`](../src/map/)（`schema.js` 形状校验、`serialize.js` 字节稳定排版、
  `terrain.js` 高程场、`ops.js` 声明式改图、`style.js` 层数↔高度）
- 命令行孪生：[`tools/plan-ops.mjs`](../tools/plan-ops.mjs)（AI 接口脱机版）、
  [`tools/generate-town.mjs`](../tools/generate-town.mjs)（生成器）、
  三道机检门 [`tools/ops-check.mjs`](../tools/ops-check.mjs) / [`tools/relief-check.mjs`](../tools/relief-check.mjs) /
  [`tools/road-walk.mjs`](../tools/road-walk.mjs)

---

## 1. 怎么起

```bash
just run-city                       # :5174
```

- 游戏：http://localhost:5174/
- 编辑器：http://localhost:5174/editor.html

两个页面同一个 dev server、同一份 `data/town-plan.json`。
`just build-city` 也会把 `editor.html` 一起打进 `dist/`（rollup 入口里有它），但**生产包里存不了盘**：
写文件的接口只挂在 dev server 上，产物里没有任何写能力，编辑器的改动只能靠「下载 JSON」带走。

编辑器打开时**总是读服务器上的最新版**（不是构建期打进 bundle 的那份）。
构建期的 `import PLAN from '../../data/town-plan.json'` 只当垫底，
万一 dev API 没起来，界面还能画出一张能看的图，只是存不下去。

改完图落盘前跑这四道（不启动浏览器，见 §10；一条命令 `just check` 全跑）：

```bash
npx vite-node tools/ops-check.mjs      # op 语义
npx vite-node tools/relief-check.mjs   # 造成几何与碰撞
npx vite-node tools/road-walk.mjs      # 行车面能不能走（可加 --file <plan> 查生成器的产物）
node tools/layering-check.mjs          # 3D 分层红线：地图/模型/材质有没有被绕过（见 docs/3D-LAYERING.md）
```

## 2. 数据流（改一处，四处跟着变）

```
data/town-plan.json（唯一真源，17,206 字节）
  ├─ GET /__plan ──────────────→ 编辑器（内存里的 S.plan，可改）
  │                                └─ 2D 平面图 + 3D 实景预览 + 造成清单 + 体检面板 + 批量改外观
  ├─ GET/POST /__plan/ops ─────→ src/map/ops.js（声明式改图：AI / 命令行 / 面板三处同一套语义）
  ├─ import（构建期垫底）─────→ src/world/layout.js  ← 导出 R/LAT0/ROADS/PLACES/SOLIDS/TERRACES/FLIGHTS…
  └─ POST /__plan ←─ 序列化（字节稳定）
                                   layout.js 的消费者们一个都没改：
                                   src/map/terrain.js   解析高程场 makeField()（§6），场/几何/碰撞/机检共用
                                   src/world/planet.js  逐像素刷地面贴图（路/人行道/广场/斑马线/沙滩/林带）
                                   src/world/town.js    42 个 builder 按材质桶合并 + 造成实体（台地/石阶/坡道）
                                   src/world/collision.js  30 类 SOLIDS 占位碰撞 + 挡墙 + 梯道扶手（每条带 from 标签）
```

`layout.js` 里那套球面映射（`planToLatLon` / `planToVec3` / `planQuat` / `normalAt`）迁移时**逐字没动**，
所以 plan 坐标 (x=东, z=南, 米) 的口径、猫踩到的碰撞盒、编辑器 2D 里的格子，是同一把尺。

迁移用的脚本留在 [`tools/migrate-plan-to-json.mjs`](../tools/migrate-plan-to-json.mjs)：
它把原来手写在 JS 里的数组倒成 JSON，并自检 `terrainH()` 在 4 个采样点上前后一致。
`hills` 当年没被 `export`，所以表是在脚本里手抄的（下方自检保证与 `terrainH` 一致）。
**这是一次性脚本，别重跑** —— 它写的是迁移前那套旧数组，跑一遍等于把后来在编辑器里改的全抹掉。

## 3. 界面分区

```
┌ topbar   撤销 · 重做 · 归位 · 森林树 · 时刻 · 地图体检 ─┼─ 保存到文件 · 下载 JSON ─┬ 保存状态
├──────────┬────────────────────────┬────────────────────┤
│ 摆物件   │  2D 平面图（主操作面）  │  属性面板          │
│ ─tab─    │────────────────────────│  世界参数          │
│ 批量改   │                        │   └ 造成清单       │
│ 外观     │  3D 实景预览（同一套 buildTown/buildPlanet）│  体检结果（可点定位）  │
├──────────┴────────────────────────┴────────────────────┤
│ 底栏：可学习物件 147 个（共 147 件）· 道路 6 条 · 造成 5 处 · 可撤销 N 步 · 批量读数 · 快捷键 │
└────────────────────────────────────────────────────────┘
```

左栏是两个 tab（**一个能力一个入口**，批量改外观不塞进属性面板）：「摆物件」管落子，
「批量改外观」管一批东西刷成什么样，见 §8。

- **2D 面**画的是真数据：地形底直接逐像素取高程场的 `field.surface(x,z)`（缓存键 = `hills`/`beachZ`/`roads`/`terraces`/`flights`），
  所以路面起伏、台地、梯道在 2D 里就是看得见的明暗；路基按 `roads` 宽 + `sidewalkW` 道牙、
  路面按 `surf` 上色（与 `planet.js` 的 `surfPatch` 同色）、广场/停车场/斑马线照 `planet.js` 的画法，
  物件符号直接取 `SOLIDS` 的碰撞盒（矩形或圆），所以**在 2D 里看着压线 = 游戏里真会压线**。
- **3D 面**是游戏里那套装配，不是简化模型：`buildTown(scene, S.plan)` / `buildPlanet(S.plan)`
  收了一份可覆盖的数据，所以预览跟成品同源。道路/广场/停车场/斑马线/山丘/海滩这几项变了才会
  重刷星球贴图（那一步要 1~2 秒，其余改动只重建小镇）。

## 4. 能做的操作

| 动作 | 怎么做 |
|---|---|
| 放物件 | 左侧调色板点一个类型（armed），在 2D 上点一下落子；`Esc` 取消 armed |
| 挪 | 2D 上拖动，0.1 米吸附，按住 `Alt` 变 0.5 米 |
| 转 | 拖选中物件外的那颗**红点**（5° 一格）；或 `Q`/`E` ±15° |
| 微移 | 方向键 0.1 米，`Shift` + 方向键 0.5 米 |
| 删 | `Delete` / `Backspace`，或属性面板「删掉」 |
| 复制 | `Ctrl+D`（+1.2 米落在旁边） |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Y`，顶栏钮同义；快照上限 200 条，一次手势算一条 |
| 改道路 | 点路的**端点**拖；属性面板改四个坐标 + 半宽 + **路面材质**（沥青/石板/砖/碎石） |
| 把路拉弯 / 拉直 | 点路的**中间折点**拖出新顶点（`＋加折点` / `拆折点`）；拉直就把三点折线改回两端点 |
| 改路面起伏 | 属性面板改逐节点高程 `e[]`（折线）或 `e1`/`e2`（直线），`efade` 控过渡裙宽；见 §6 |
| 加台地 / 石阶 | 右栏「世界参数 → 造成」里「＋ 加一块台地」「＋ 加一条石阶」，落在视图正中，尺寸/抬升/边处理在属性面板改 |
| 批量改外观 | 左栏「批量改外观」tab：先筛一批（类型/半径/上限/抽样成），再刷一类（外墙色/屋顶色/层数/外观号/尺度），见 §8 |
| 让 AI 改 | `GET /__plan/ops` 拿说明书，`POST /__plan/ops` 提交一批 op，见 §7 |
| 改世界参数 | 右栏「世界参数」：R、中心纬度、人行道宽、海滩起点、广场圆心/半径、停车场四边 |
| 看它 | 属性面板「3D 看它」→ 预览相机飞过去；选中项地面有红色光环 |
| 平移 / 缩放 | 右键（或中键）拖动平移，滚轮以光标为锚缩放（4~80 px/米） |

浮条规矩：**动了数据的动作都配一条反向写的**（「放了一个便利店 → 拿掉它」「删掉了一个物件 → 把它放回来」），
顶栏只留撤销/重做两个真按钮。计数（可学习物件/道路/造成/可撤销步数/批量命中）在底栏，不进顶栏。
浮条上的反向动作**只能挂 app 的包装函数**（`doUndo`/`doRedo`），不能挂 `state.js` 裸的 `undo`/`redo` ——
裸函数只换数据，不刷 2D/3D/属性面板/底栏，点了等于什么都没发生（这轮真踩过，见 §12）。

## 5. 体检判据（`src/editor/problems.js`）

阈值是**照着现有这张图校准的**，不是拍脑袋：初版把樱花（站在沙滩环上）、森林树（d≈44）、
车站（正对主街尽头）全报成问题，27 个误报。现在这三类都有明确豁免，跑真图报 **0 条**。

| 级别 | 判据 | 为什么这么定 |
|---|---|---|
| err | `kind` 不在 `BUILDERS` 里 | 游戏里凭空消失 |
| err | `word` 不在 514 词库里 | 拍照即报错 |
| warn | `word` 为空 | 拍不到，但不坏 |
| err | `z > 30.5` | 已经是海，物件飘水上 |
| err | `z > 23.5` 且不是植物 | 沙滩带该放树/樱/花/草簇 |
| err | `hypot(x,z) > 46` | 超出城镇帽（贴图带只到纬度 +90°/−30°） |
| warn | 森林树出林带（`d>46` 或 `z>24` 或 `z<-34`） | 只是稀疏背景，不崩 |
| warn | 建筑中心到路中心线 `< w + 0.2` | 会被卡在墙外；只有 `BUILDING_KINDS` 那 13 类参与判定（路灯/信号灯/杆类本来就该站在路牙上，压根不在名单里），`station` 单独豁免（设定就是正对主街尽头） |
| err | 两个建筑 footprint AABB 相交（盒先乘 0.86） | 0.86 是因为外观普遍没占满碰撞盒，紧贴摆放是合法的 |
| err | 台地台面盖住某条路的**中心线**（挡墙边、h>0.15） | 挡墙会从马路中间穿过去，猫直接被墙堵在街上 |
| warn | 台地边线压到道路的人行道带（`w + sidewalkW`） | 道牙会歪，但还走得通 |
| err | 建筑四个角跨在同一块挡墙两侧 | 房子一半在台顶一半在台下，会被切开 |
| warn | 挡墙四周没有接上的石阶/坡道 | 猫只能绕着走（顶标高差 ≤0.3 米才算真接上） |
| err | 石阶/坡道压在行车面（离中心线 < `w`） | 梯道本体占了车道 |
| err | 每级踢面 >30 厘米、或升高 1 米只走 <1.1 米 | 猫一步跨不上去 |
| err | 造成伸出城镇帽、台地 h 不在 −1.5~2.5 米 | 几何会悬空或插进星球网格 |

`有 err 就拦保存`（浮条给一条「照样保存」），warn 不拦。

注意 **`station` 的豁免只在上面那条 warn**：它是「建筑贴着路」的语义豁免（车站就该站在街口），
不代表站房可以压在行车面上 —— 压没压由 §10 的 `tools/road-walk.mjs` 按猫的碰撞表判，那一层谁都不豁免（只有 `car` 除外）。
这轮的真缺陷就是这么漏网的：站房正好站在主街中心线上，`warn` 规则看不见它，碰撞表一查就露。

## 6. 高程场：路面起伏、台地与梯道（`src/map/terrain.js`）

一张 plan 里能抬高地面的东西有三类，全部由**同一个解析函数**算出，没有烘焙网格：

| 表 | 字段 | 落地成什么 |
|---|---|---|
| `roads[]` | 折线 `{pts,e[],w,efade,surf}` 或直线 `{x1,z1,x2,z2,e1,e2}`；`e` 就是逐节点的设计抬升（米） | 行车面跟着 `e` 起伏，`surf` 换材质（沥青/石板/砖/碎石） |
| `terraces[]` | `{x,z,rotY,hw,hd,h,edge,apron}` | 一块水平填方台面；`edge:"wall"` 出挡墙（带碰撞），`"slope"` 按 `apron` 放坡 |
| `flights[]` | `{x,z,rotY,w,run,rise,steps,kind}` | 石阶（`stair`）或坡道（`ramp`），两侧出扶手碰撞 |

场分两半，**游戏里的猫和 2D 底图用 `surface`，星球网格用 `mesh`**：

```
hillsH(x,z) = Σ 丘陵高斯                       // 自然起伏
roadElev(x,z) = Σ(k²·e) / Σk² × (1 − Π(1−k))  // 多条路在此相遇 → 按归属感加权平均
relief(x,z)   = 梯道优先；否则 max(roadElev, 台地)
surface       = hillsH + relief                // 猫真踩的面
mesh          = hillsH + roadElev              // 地面贴图/网格（不含造成，造成另有实体）
k = influenceK(到中心线的横向距离, w + sidewalkW, efade ?? 3.0)   // 路带内 1，裙边 smooth 衰减到 0
```

两个关键点，都是踩出来的：

- **路口不能「谁近听谁的」**。两条设计标高不同的路在路带重叠处硬切换，切换线就是一道 0.7~0.9 米的垂直坎，
  猫走过去等于瞬移上/下台。改成按 k² 加权平均后，混合在空间上连续，路口板落在两者之间；
  单条路仍是 `e·k`（乘覆盖度那一步保证裙边外照旧归零）。全零抬升的路不参与（`on=false`）——
  一条平路不该把旁边的高路堤拽回地面。
- **`influenceK` 是场和机检共用的唯一口径**。`tools/road-walk.mjs` 判「路口污染」也调它，
  工具不许自己臆造一套「什么算压到路」。同理 `deckLevel`/`flightLevel`/`flightFeedsTerrace`（顶标高差 ≤0.15 米才算接上）
  被挡墙开口、挡墙碰撞、体检三处共用，否则会出现「墙上开了口但碰撞还挡着」。

## 7. AI 改图接口与命令行孪生

界面能做的，脚本一定能做 —— 两边共用 [`src/map/ops.js`](../src/map/ops.js) 这一套语义，不会出现「编辑器里有个按钮、AI 调不出来」。

- `GET /__plan/ops` → `{version, ops, where, rules, file}`：op 清单、筛选器说明、规矩，AI 照着写。
- `POST /__plan/ops` → body `{ops:[…], dryRun?, sha?}`：读磁盘 → `applyOps` → 形状校验 + `checkPlan` → 才落盘。
  **有一条 op 写歪 → 422 且整批不落盘**；改出来的图不合法 → 422 不落盘。`dryRun:true` 只回报不写。
- 命令行孪生 [`tools/plan-ops.mjs`](../tools/plan-ops.mjs)：`--ops <JSON>` / `--file ops.json` / `--stdin`，
  配 `--dry-run`、`--out <文件>`、`--doc`（打印全部 op 与筛选器）、`--list`（只看现在有什么可改）。默认写盘，同样两道关。

op 词汇表（`place` / `tree` / `road` / `terrace` / `flight` / `hill` 六张表 × `add|set|move|remove`，
外加 `place.style`、`place.scatter`、`plan.set`）；筛选器 `where` 支持
`kind`/`kinds`/`surf`/`word`/`ids`/`has`/`box`/`near`/`limit`/`every`。四条硬规矩：

1. `applyOps` 是纯函数：同 plan + 同 ops + 同 seed ⇒ 逐字节相同的结果（可复现、可写进文档）。
2. `where` 省略＝整表；**筛到 0 条一律报错**，不静默空转。
3. 字段名走白名单，非数字的值被拒并报错。
4. 层数只有 `mansion/tower/office/hotel` 有，且夹在各自 `min~max` 内。

道路形态是个坑，接口替调用方填平了：真源里**直线与折线二选一**（`validatePlan` 见到 `pts`+`x1` 直接拒），
但 `road.set` 只写你给的那几个键。于是 `normalizeRoadForm` 按「这次写了哪套」让另一套让位——
写 `pts` 就删掉直线端点、`e` 缺省按原本 `e1→e2` 逐节点线性铺（**不把坡度悄悄清零**）；
写 `x1/x2` 就把折线拉直、`e` 首尾折回 `e1/e2`。

这轮真用它修过一张图：[`tools/ops-station-forecourt.json`](../tools/ops-station-forecourt.json)（两条 op：
`place.move` 把咖啡 #7 挪开 → `road.set` 把主街重排成穿过站前广场的折线，并给五个节点各自设计抬升）。
现成例子还有 [`tools/ops-clear-lane.json`](../tools/ops-clear-lane.json)。

## 8. 批量改外观（左栏第二个 tab）

面板**不自己写 plan**：它把控件状态拼成一条 `place.style` op，交给同一个 `applyOps` 算出新图再提交。
所以「界面上点的」和「AI 发的」是同一份代码路径，`tools/ops-check.mjs` 也能直接拿这条 op 做机检。

- **改哪些**：类型 + 「只改屏幕中心 N 米内」+ 「最多改几条」+ 「随机抽几成」，底栏实时报命中数（计数不进顶栏）。
- **改成什么样**：外墙色 / 屋顶色（各自可选「都涂这个色」或「一栋一个样：6 套米色/6 顶瓦色里随机」）、
  层数（统一 N 层，或「高低错落：lo~hi 随机」）、外观编号、尺度。
- **随机种子**写在面板里，同种子＝同一批结果；随机候选色与 `props.js` 色板同源，不会刷成大红大绿。
- **按一次「就改这些」＝一条撤销**：整批只压一条快照，浮条给一条「改了 N 个物件的外观 · 公寓楼：4~6 层错落 → 改回去」。
- 面板会按类型说清这一型能盖多高（`这一型 2~8 层、层高 1.35 米；拉满 8 层约 11.65 米高`），
  选了不吃层数的类型就把层数那一行灰掉，不让人白点。

## 9. 地图生成器（`tools/generate-town.mjs`）

以现有真源为底（保留词条与街具位置），重做四件事：

1. **纵向剖面**：每条路按 seed 驱动的正弦 + 缓坡生成起伏，并把折线节点、路口分段点都补成可控点（每 3 米一档）。
2. **路口同高**：两条路的行车面带一旦重叠，把重叠段内所有控制点松弛到同一水平。
   高程场现在在路口是连续混合的，不同高**也不会再留垂直坎**，但混合出来的路口板会斜着翘——
   松弛成同高，路口就是一块水平板，猫走进去不掉高。
3. **沿街净空**：只把真咬进行车面的东西（碰撞盒越过道牙）沿法向让到车道外沿，留 0.15 米余量，跑两遍。
   人行道上的路灯/长椅/售货机是设定，**不许推**；豁免表只有 `car` —— 站房压路也得让位。
4. **高楼**：给吃层数的 kind 重新分配层数（seed 驱动，夹在各自 `min~max`）。

```bash
npx vite-node tools/generate-town.mjs --seed 7                    # 只算，打 stdout，不写盘
npx vite-node tools/generate-town.mjs --seed 7 --out /tmp/x.json  # 另存
npx vite-node tools/generate-town.mjs --seed 7 --write            # 备份后写回 data/town-plan.json
npx vite-node tools/generate-town.mjs --clear-only --write        # 只让位，不重做剖面/材质/层数（手写图专用）
```

`--clear-only` 是给「图是手搓的、只想清行车面」的场景：跳过 §1/§4 的剖面与层数重排，只挪东西 + 落盘前照样过校验。
本轮磁盘上那张图就是这么修的（65 件街具让位），路面起伏与层数一个都没被重排。

**出图前必过两道关**，任何一条 err 都不写盘：`validatePlan`（形状）+ `checkPlan`（游戏里会不会出怪事）。
上一版只有前者，于是生成器能理直气壮地产出一张「形状合法、站房压在马路中间」的图。

## 10. 四道机检门（前三道 `npx vite-node tools/<gate>.mjs`，第四道裸 `node`）

规矩：**每条断言都得带一条 control 证明它不是空转**（同一种探针在「本该命中」的地方必须命中），
否则「全绿」只说明脚本什么都没查。

| 门 | 查什么 | control 怎么自证 |
|---|---|---|
| [`ops-check.mjs`](../tools/ops-check.mjs) | op 语义：筛选器、`limit/every` 随机、直线↔折线互转、`e` 不被悄悄清零、`place.scatter` 沿街摆、综合脚本零报错 | 真源里必须**直线与折线并存**（样本按形状挑：直线带坡 #1／折线 #0／最长 #0＝61 米，不写死某条路的索引、不拿某条路的坡度值当常量）；`pts` 与 `x1` 恰好有一个（schema 的 XOR 在真源里成立）；一条 `place.set` 只动 streetlight 那一型时**其余 141 个物件一字节未动**；写越界层数/越界色号走 `place.set` 也被夹（不是只有 `style` 设防）；两色随机要**两色都真被抽到** |
| [`relief-check.mjs`](../tools/relief-check.mjs) | 造成几何与碰撞：台地挡墙真出了实体、墙上开口按梯道让位、虚拟猫撞墙要能被推出、材质桶不丢属性 | 造成这一趟必须**真产出 19 块几何**（台地 3 + 梯道 2，各自都不止一块）；「石阶口子前无阻」必须配「口子旁 1.6 米是墙身、虚拟猫被推出」，否则探针根本没走路；离路口 14 米处仍各自照自己的剖面（−0.1 / 0.9 米）—— 证明**混合只发生在路口，没把全线拉平** |
| [`road-walk.mjs`](../tools/road-walk.mjs) | 行车面能不能走：道牙扫掠、实体压路（`hits` vs 只啃到一点 `nibbles`）、**中心线上猫的碰撞表**（`paved` 寸步不许 + `tight` 连 0.18 米猫身余量都不够）、设计抬升有没有落地、每步落差 ≤0.15 米 | 在同一处「不该豁免的东西」（站房 #0 正中心）上，`buildingAt` 与 `colliderAt` **都必须探得到** |
| [`layering-check.mjs`](../tools/layering-check.mjs) | 分层红线：地图真源没被手写进 JS、`src/map/` 不碰 three、高程与碰撞单一来源、数据层不吃随机、页面不落盘；three 构造点（材质/几何/合并）计数只准减不准增（基线 337 处） | 注入的合成文件六类违规 6/6 被抓；「新文件／变胖／变瘦／相等」四种情形各判对；真源文件里必须量得到构造点（`materials.js` ≥5、`props.js` ≥20…）证明正则没瞎；**端到端实测**：真往 `src/map/style.js` 塞 `import 'three'`、往 `src/world/planet.js` 塞 `new THREE.MeshStandardMaterial`，两次都 FAIL 且跑完按 md5 还原 |

`road-walk` 的碰撞项查的是 `src/world/collision.js` 那张**猫真踩的表**（比 `SOLIDS` 多出台地挡墙、梯道扶手、树林），
这正是「有垂直高差必须有东西挡着」那一族缺陷的探测器。`--file <plan>` 可以查生成器的产物，
但 `COLLIDERS` 与 `layout.groundHeight` 是照**磁盘真源**在模块加载时建的 —— 查别的文件时这两项**明说没查**（打 `note`），
既不静默通过，也不报假失败。

碰撞表每条都带 `from` 标签（`station #0`、`terrace #1 side+`、`flight #0 rail−`、`forestTree`），
机检和调试才说得出「是谁堵的」而不是「这里有个盒子」。

## 11. `__plan` 接口与安全边界

只挂在 dev server（[`vite.config.js`](../vite.config.js) 的 `townPlanDevApi`）：

- `GET /__plan` → `{sha, plan}`；`sha` = djb2 内容指纹（`hex:字节数`），编辑器用它判「服务器版还是不是我打开时那一版」。
- `POST /__plan` → 先 `JSON.parse`，再过 `validatePlan()`，才 `writeFileSync`。形状不过关一律 400，**不碰磁盘**。
- 请求体上限 4 MB，超了直接 `req.destroy()`。
- 保存流程是**先 GET 比 sha、再 POST**：sha 对不上就是别处改过文件，弹确认（选「重新载入服务器版」放弃本地，或取消保住本地不动盘）。
  这一判只保证 dev 单人改图不被互相覆盖，不是事务 —— 两个编辑器同时点保存仍可能后者赢。

实测（2026-10-07）：

| 灌进去的东西 | 服务器答 |
|---|---|
| `{"R":"x"}` | 400 `R 必须是数字` |
| `not json` | 400 `JSON 解析失败: …` |
| `places:[{x:1}]` | 400 `物件必须有数字 x/z` |
| `roads:[{…缺 w}]` | 400 `道路缺少数字字段 w` |
| `places:[]` | 400 `places 不能为空（存下去小镇就没东西了）` ← 这条是验收时才发现漏了、补上的 |
| `roads:[]` | 400 `roads 不能为空（存下去就没路了）` |
| 合法且完整的 plan | 200 + 新 sha |

上一轮验收顺带挖出并修掉的四个真 bug：

1. `view2d.js` 人行道线宽写成了 `sidewalkW*2`，比沥青（`w*2`，w=2.2）还窄 → **2D 里从来没画出过人行道**。改成 `(w + sidewalkW)*2`，与 `planet.js` 的 `w..w+SIDEWALK_W` 同口径。
2. `view3d.js` 把相位表原行直接喂给 `applySkyUniforms()`，而表里颜色是**十六进制数字**；`Color.copy(数字)` 读出 `undefined` → 太阳/半球/雾/天空全变 NaN → **预览整屏黑**。游戏传的是 `lerpPhase()` 之后的对象，所以只有编辑器中招。改成 `lerpPhase(raw, raw, 0, {})`。
3. 预览轨道圆心写成 `(0, R, 0)`（那是 +Y 顶点，不是图面原点，因为 LAT0=38°）→ 相机绕错点，飞过去也找不到东西。改成 `planToVec3(0,0,0)`。
4. `validatePlan()` 只查形状，`places:[]` 能过 → **一次保存就把小镇清空了**。补了 places/roads 非空两条。

这一轮又挖出五个（都是「机检全绿但图是坏的」或「界面看着没反应」那类）：

1. **站房正站在主街中心线上**。`checkPlan` 那条「建筑贴路」只是 warn 且 `station` 豁免，所以体检一声不吭；
   真正暴露它的是把**猫的碰撞表**搬进 `road-walk` 之后（中心线上 pad 0 就叫 `paved`）。修法是走 AI 接口，不是手改 JSON：
   `tools/ops-station-forecourt.json`（挪开咖啡 #7 → 主街重排成穿广场的折线）+ `generate-town.mjs --clear-only --write`（65 件街具让位）。
   站房现在在 `(-4.63, -16.01)`，主街中心线上寸步无阻。
2. **路口用「谁近听谁的」选高程** → 两条设计标高不同的路在路带重叠处硬切，切换线是一道 0.7~0.9 米的垂直坎，猫走过去等于瞬移上/下台。
   换成 `k²` 加权连续混合（§6），并把 `influenceK` 提成场与机检共用的唯一口径。
3. **浮条上的反向动作挂的是 `state.js` 裸 `undo`/`redo`**，不是 app 的 `doUndo`/`doRedo`。
   裸函数只换数据、不走 `afterPlanSwapped()`，于是按「重做到这一步」之后：数据真重做了，
   但 2D/3D/属性面板/底栏「可撤销 N 步」全停在旧图，浮条还留着上一条「已退回改动前」——
   看上去就是「撤销按钮没用」。改成挂包装函数，并给 `float()` 加了序号保护（动作自己开了新浮条时，别再把刚显示的那条藏掉）。
4. **生成器把 `station` 也当成行车面豁免**（照抄了 `road-walk` 早期那张 `^(station|car)$` 的表），
   于是让位阶段报「挪了 63 件」却把站房原样留在马路中间。两处豁免统一到只有 `car`，
   并且让位改成两遍跑（挪完可能被邻件再挤一次）。
5. **`ops-check` 自己也在空转**：样本用 `roads.findIndex(r => r.e1 === 0.45)` 挑，图上有多条带坡度的路时
   它悄悄落到 12 米长、挤满街具的那条，`place.scatter` 摆出 0 盏灯，而断言只查「报了数」不查「数不为 0」→ 绿着漏过。
   现在按**形状**挑样本（直线带坡 / 折线 / 最长），并断言 XOR（`pts` 与 `x1` 恰好有一个）在真源里成立。

## 13. 已知限制 / 没做的

- **不改模型本体**：编辑器与批量改外观只管数据（落点/朝向/尺度/词条/外墙色/屋顶色/层数/外观编号），
  几何形状本身在 `src/world/props.js`，要新造型得改代码。
- **批量改外观按筛选器命中，不是 2D 框选**：能在地图上「以某点为中心 N 米内」挑一批，
  但还不能拉一个矩形框；单个物件的逐件编辑走属性面板。`snapshot()` 上限 200 条，超了丢最老的。
- **改 `R`/`LAT0` 会连带重算地面贴图**（1~2 秒），期间预览显示「正在重建 3D 预览…」；这两个值动大了，游戏里猫的行走面也得重算才自洽。
- **冲突判定靠 GET 比 sha，不是事务**，见 §11。
- 体检不查「物件离得太远玩家走不到」「同一地块重复单词」这类语义问题。
- 森林树与 `places` 是两张表（`forestTrees` 无词、纯背景），编辑时靠「森林树」开关切显示，但它们共存于同一份 JSON。
- 生成器是**在现有真源上重排**（剖面/净空/层数），不是从零摆一张图；词条与街具位置会被保留，路面材质与建筑落位仍需人（或 AI 发 op）来定。
- 机检门的 `road-walk --file` 只能查形状与解析场；`COLLIDERS`/`groundHeight` 两项绑磁盘真源，查别的文件时明说没查（见 §10）。
- 生产包里存不了盘，实测过：`just build-city` 会出 `dist/editor.html`，用 `vite preview` 打开后
  `/__plan` 不存在（静态主机会给 404，`vite preview` 给的是 SPA 兜底的 HTML），
  起界面显示「读服务器失败，用构建期垫底数据：…」，点保存显示「保存失败：Unexpected token …」，磁盘一个字节都不动。
  `/__plan/ops` 同理只挂在 dev server 上。
  界面本身照常可用（143 件、亮像素 0.98），但要落盘只能靠「下载 JSON」带走。
  要上线编辑能力得另做后端，不是把这个中间件挪过去就完事。
