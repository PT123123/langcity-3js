# LangCity 3JS — 交接规格书（给实现 Agent）

> 本文档自洽，不需要回头读原 Godot 项目即可开工。
> 原项目（视觉与数据参考，只读）：本地 Godot 项目 `LangCity`
> 目标目录（在这里写代码）：本仓库根目录

---

## 0. 任务一句话

用 **Three.js** 复刻 LangCity（Godot 日语学习游戏）的**核心体验**：
第三人称小猫漫步在一颗**低多边形日式小镇星球**上，走近物体出现金色光圈，
点击它弹出**日语单词卡**（汉字/假名/罗马音/中文）并发音。

**用户原话的两个重点：**
1. **「我比较看重视觉」**——视觉是这个项目的第一验收标准，玩法可以薄。
2. **「做最有性价比的部分就行，Three.js 没多高性能」**——把钱花在色彩/光照/构图上，
   不花在真实感细节、SSAO/SSR 这类昂贵后处理上。

## 1. 玩法 MVP 范围（先保这个闭环）

| 功能 | 说明 |
|---|---|
| 星球行走 | 球形重力（重力指向球心），WASD/方向键移动 + 屏幕拖动/鼠标转动视角；可绕星球走一整圈 |
| 第三人称小猫 | 真实猫比例（肩高~0.23m）的程序化小猫，走路摆腿动画，可跳（跳高 0.66m） |
| 金色光圈 | 走近可学习物体（≤2.2m）时物体脚下出现金色光圈 + 微微上下浮动 |
| 拍单词卡 | 对准光圈物体按【拍照】（键 F / 屏幕按钮）：白闪+快门音 → 弹单词卡 |
| 单词卡 | ja（汉字）/ kana / romaji / zh / 分类色标；首次发现显示 NEW WORD；自动发音（Web Speech API，lang=ja-JP，不可用时静默跳过） |
| 词汇库 | 抽屉式列表，按分类显示进度条（街道 4/13），点条目重新发音 |
| 存档 | localStorage：已发现单词 id 集合 + 玩家位置 |
| 小地图 | 左上圆形小地图：星球俯视 + 物件点 + 玩家朝向（可选，后置） |

**不做**：室内、任务系统、复习测验、NPC 对话（README 里写进「后续路线」即可）。

## 2. 视觉规格（本项目的心脏，逐条执行）

### 2.1 风格定义

> **Stylized 3D / 可进入的 3D 插画（Playable Illustration）/ Soft Realism**

不是低模积木（禁止 Minecraft/Roblox/纯色块 Flat 风），不是写实，不是卡通 Q 版。
公式：**保留真实物体的识别特征和比例，主动删除细小结构，边缘略圆润，材质简化，靠柔和光照表现体积。**

一眼验收标准：「这是椅子。」但玩家不会去想「椅子螺丝是什么材质」。
**随便截一张图，应该像一张完整的 3D 插画。**

### 2.2 色彩系统（最重要，先调色再建模）

低到中饱和，**整个场景一个色彩环境，而不是每个物体各自鲜艳**：

| 用途 | 色值建议 |
|---|---|
| 柏油路面 | #6b6663 ~ #75706c（暖灰） |
| 人行道砖 | #a89f92 / #b5ab9c 交替微差 |
| 建筑墙 | 米白 #ece5d8、淡灰 #d9d4cb、淡黄 #e8ddb9、柔和砖红 #c99a83 |
| 屋顶瓦 | 暖灰绿 #8d968a、暖灰蓝 #97a3a8、深灰 #7b7772 |
| 植物 | 灰绿系：#8fa876 / #7d9a6c / #6f8b60（**禁用纯绿 #00ff00 系**），樱花 #e8c9cf |
| 水/海 | 柔和蓝绿 #7fb3b5 |
| 天空（黄昏★默认） | 顶 #5b6b8c → 中 #b98a8f → 地平线 #e8b27d |
| UI 和纸底 | #f7f3ea，文字 #4a4238 |
| UI 朱红点缀 | #c94f4f |

### 2.3 材质规则（性价比之王：调 roughness/metalness，不加细节）

统一 MeshStandardMaterial，**核心是把粗糙度分档拉开**，消除塑料感：

| 语义 | roughness | metalness | 用于 |
|---|---|---|---|
| 混凝土/外墙 | 0.88 | 0 | 墙、台阶 |
| 沥青 | 0.95 | 0 | 路面 |
| 铺装砖 | 0.80 | 0 | 人行道 |
| 瓦 | 0.68 | 0.05 | 屋顶 |
| 木 | 0.76 | 0 | 招牌框、长椅 |
| 叶片 | 0.82 | 0 | 树冠（微 emission 0.05 模拟透光） |
| 深叶 | 0.88 | 0 | 灌木 |
| 朱红塑料 | 0.35 | 0.1 | 贩卖机机身 |
| 白塑料 | 0.40 | 0 | 面板 |
| 深色金属 | 0.42 | **0.85** | 电线杆 |
| 镀锌铁 | 0.55 | **0.75** | 空调外机、垃圾桶 |
| 玻璃 | 0.06 | 0.3 | 窗户（黄昏/夜里改自发光） |
| 橡胶 | 0.92 | 0 | 轮胎 |
| 霓虹/灯箱 | MeshBasicMaterial | — | 招牌发光字、灯箱面 |

**材质微差（必做，成本≈0，收益巨大）**：同一材质的多个实例按世界坐标 hash 做
明度 ±5.5% 抖动 + 轻微色相偏移，每块砖/每扇窗/每棵树冠各不相同。
这是消除「同一个颜色出现 200 次」塑料感最便宜的手段。
实现建议：写一个 `jitteredMat(baseColor, rough, metal, worldPos)` 工厂缓存实例。

### 2.4 光照（风格核心，禁止「一个方向光+环境光完事」）

- HemisphereLight（天光，天空蓝灰 → 地面暖灰，强度按时刻调）
- DirectionalLight（太阳/月亮）+ **PCFSoftShadowMap**，shadow.mapSize 2048（低端 1024），
  阴影相机只包住玩家周围 ~60m（跟随玩家移动），bias 调好防痤疮
- 补一盏与太阳反向的低强度冷色 fill（强度 0.15~0.25，无阴影），避免暗部死黑
- 环境光强度宁高勿低：**阴影区域必须仍能看清物体**
- 小物件（电线杆/邮筒/贩卖机/垃圾桶）**不投实时阴影，脚下贴 Blob Shadow**
  （径向渐变圆片贴地，透明度 ~0.25，黑色偏棕）——廉价但解决「浮在地面」

### 2.5 四时刻系统（默认黄昏★）

实现 `applyTimeOfDay(phase)`，四套参数插值过渡（15s 或点击即切）：

| 参数 | 朝 6:30 | 昼 12:30 | **夕 18:00★默认** | 夜 21:30 |
|---|---|---|---|---|
| 太阳仰角 | -16° | -58° | **-13°** | 月亮 -40° |
| 太阳强度 | 0.95 | 1.35 | **1.5** | 0.45 |
| 太阳色 | 暖橙 #ffb27a | 冷白 #fff4e0 | **暖橙 #ff9e5e** | 月光蓝 #8fa8d8 |
| Hemisphere 强度 | 0.28 | 0.34 | **0.42** | 0.5 |
| 窗户自发光 | 0.25 | 0 | **0.85** | 1.0 |
| 街道点光强度 | 0.5 | 0 | **0.85** | 1.0 |
| 雾色 | 暖米 #d8c9b0 | 冷白 #dfe3e8 | **橙褐 #c9957a** | 深蓝紫 #2b2f4a |
| Bloom 阈值 | 0.82 | 0.9 | **0.72** | 0.5 |

- 雾用 `scene.fog = new THREE.Fog(色, near≈60, far≈220)`，是空气感最便宜的来源
- **夜景铁律（原项目踩过的坑）**：夜景不是把光调暗就完事——月光弱但**必须有方向**，
  Hemisphere 提上来保证轮廓可读，明暗层次靠**窗户自发光 + 路灯 PointLight + 霓虹**做。
  否则画面糊成黑块。
- **Bloom 铁律**：自发光材质的 emissiveIntensity 必须 > 1（灯箱 2.6、路灯 3.2、霓虹 4.0）
  才会被 UnrealBloomPass 捕获，低于 1 只是白板。

### 2.6 后处理（克制！最后加，出问题先砍它）

- 渲染器：`ACESFilmicToneMapping`，`toneMappingExposure≈1.0~1.1`，`outputColorSpace = SRGBColorSpace`
- EffectComposer：**RenderPass + UnrealBloomPass(strength 0.35, radius 0.5, 按上表阈值) + OutputPass**
- 额外自制一个全屏 ShaderPass：Vignette（0.3，深棕 #2a2018 而非纯黑）+ 胶片颗粒（0.02）
- **禁止**：SSAO、SSR、强景深、强锐化、色差、镜头光晕、God rays——全是性能黑洞或廉价感
- 性能兜底：Bloom 的 renderTarget 分辨率减半；`renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`

### 2.7 构图与场景设计

- **少量高质量元素 + 合理布局 > 大量模型堆砌**。每条街：建筑 → 人行道 → 植物 → 街具 →
  少量车 → 前中后三层景深 + 留白
- 「微缩世界」感：建筑不需要真实尺寸，星球半径 ~30m 即可，街道窄，一切圆润可爱
- 树是**构图元素**：不同大小/形状/灰度，聚簇摆放，不要等距阵列

### 2.8 UI（安静，视觉重量必须低于世界）

- 半透明和纸色面板（rgba(247,243,234,0.92)）、圆角 14~18px、小阴影、无厚边框
- 字体：Noto Sans JP（Google Fonts CDN 即可），标题可用衬线
- 单词卡：竖排感的大号汉字 + 假名 + romaji 灰色小字 + 中文 + 分类色条 + 【发音】按钮
- HUD 元素少：左上小地图（可选）、右下拍照圆钮、左下摇杆（触屏）、右上词汇库按钮

## 3. 技术方案

- **Vite + three（npm）+ 原生 ES Module JS**（不引框架、不用 TS 也可，保持零门槛可跑）
- `npm create vite@latest . -- --template vanilla` → `npm i three`
- 后处理从 `three/examples/jsm/...` 导入（EffectComposer/RenderPass/UnrealBloomPass/OutputPass/ShaderPass）
- 全部几何程序化生成（Box/Cylinder/Sphere/Extrude/Lathe/合并 BufferGeometry），
  **不加载任何外部模型/贴图**——贴图最多用 Canvas 程序生成（窗格、砖缝、招牌文字）
- `BufferGeometryUtils.mergeGeometries` 合并静态几何，按材质分组，控制 draw call < 300
- 树冠/栏杆/砖块等重复元素用 InstancedMesh
- 声音：WebAudio 程序生成快门音（短白噪+click 包络）；发音用 speechSynthesis（ja-JP）
- 文件结构建议：
  ```
  index.html  src/main.js        入口 + 渲染循环
  src/world/planet.js         星球本体+地形散布
  src/world/town.js           建筑与街具布局（数据驱动）
  src/world/props.js          各物件构建函数 build{House,Vending,...}
  src/world/materials.js      材质工厂 + 微差
  src/world/sky.js            天空渐变穹顶 + 四时刻参数
  src/player/cat.js           小猫 + 球面行走
  src/player/camera.js        第三人称跟随
  src/game/interact.js        光圈/拾取/拍照
  src/game/words.js           词库（内联 starter + 可选读 data/words.json）
  src/game/vocab.js           词汇库 UI + 存档
  src/ui/hud.js               HUD/单词卡
  data/words.json             从原项目复制（LangCity/data/words.json，514 词）
  ```

- **分层红线（2026-10-07 补，实现之前先读）**：地图、模型、材质都只能通过框架的入口操控，
  不许在功能文件里手撸 —— 真源只有 `data/town-plan.json`（改它走 ops／编辑器／生成器），
  材质只走 `src/world/materials.js` 的 `mat()`/`BUCKETS`，形状只在 `src/world/props.js` 的 `buildXxx()`，
  地面高程只有 `src/map/terrain.js` 的 `makeField()`，碰撞只由 `SOLIDS` 推。
  归属表、「手撸 → 正路」对照、以及以后改 3D 的五步动作在 [`docs/3D-LAYERING.md](3D-LAYERING.md)；
  仓库根 [`AGENTS.md`](../AGENTS.md) 是给 AI 的提示词路障，`node tools/layering-check.mjs` 把它变成机器门（`just check` 一起跑）。
  上面「全部几何程序化生成」这条仍然成立，但它约束的是**产物**，不是**在哪儿敲 `new THREE.`**——
  程序化生成也要通过这几层的入口，否则 §2 的色彩/粗糙度体系会在某个角落里悄悄失守。

## 4. 星球与城镇布局

- 半径 R≈30 的球。**上半球冠**（纬度 10°~62°）是城镇岛：地形用球面噪声做 2~3 个缓坡起伏 +
  一圈浅滩水色（球面下半部渐变为海），背面留少量树林（可走但内容稀疏）
- 主地图数据直接在 JS 里写一张表：`{kind, word, lat, lon, rotY}`（经纬度比像素坐标直接）
  - **2026-10-07 更新**：这张表已挪到 [`data/town-plan.json`](../data/town-plan.json)，`layout.js` 变成只导出的薄壳；
    坐标口径从经纬度换成 plan 米制 `{kind, word, x, z, rotY}`（`x` 东、`z` 南，球面映射仍由 `planToVec3` 做）。
    可视化编辑走 `:5174/editor.html`，见 [MAP-EDITOR.md](MAP-EDITOR.md)
  - **同日第二轮（路面与外观）**：路不再是一片平 —— `roads[].e[]` 给纵向起伏、`surf` 换材质（沥青/石板/砖/碎石），
    新增 `terraces[]`（台地+挡墙）与 `flights[]`（石阶/坡道）两张「造成」表，全部由 `src/map/terrain.js` 的解析高程场统一算，
    猫踩的面/地面网格/挡墙碰撞/2D 底图共用同一个口径；建筑加了 `floors` 层数（`mansion/tower/office/hotel`，最高 11 层≈16 米）；
    改图有三种等价入口：编辑器「批量改外观」面板、`GET/POST /__plan/ops`（AI 说明书就在 GET）、`tools/plan-ops.mjs`（命令行）；
    一张新图也能由 `tools/generate-town.mjs` 生成。落盘前后三道机检门（§10 of MAP-EDITOR）。详见 [MAP-EDITOR.md](MAP-EDITOR.md) §6–§12
- 参考 LangCity 城镇构成（245 物件的 kind 分布）：车站×1、便利店×1、拉面店×1、
  咖啡店×1、超市×1、邮局×1、民居×12、公寓×4、电线杆×6、路灯×6、贩卖机×5、
  垃圾桶×4、邮筒×3、长椅×4、树×12、樱×8、花×10、草×8、车×4、自行车×4、
  盆栽×10、消火栓×4、晾衣杆×5、npc×14、狗×2 猫×2 鸟×2、神社×1、学校/医院/银行/警察局/图书馆各×1
- **布局原则**：以「车站前广场」为中心 → 商店街（贩卖机/招牌/拉面/咖啡）→
  住宅区（民居+围墙+晾衣杆+盆栽）→ 公园（樱+长椅+喷泉）→ 海边（船+灯塔可选）
- 物件都写成 `buildXxx()` 函数返回 Group，注册 `{word, interactRadius, label}` 元数据

## 5. 交互细节

- Raycaster 拾取：优先精确 mesh；拾取不到就按最近的可交互物件（距准星射线 < 1.2m 且在 2.2m 内）
- 金色光圈：RingGeometry 贴地 + additive 自发光 #ffd27a，脉动缩放动画；物体同时缓慢上下浮动 ±0.03m
- 拍照：全屏白色 div 快闪 120ms + 快门音 → 弹卡；首次自动 speechSynthesis 朗读 ja 字段
- 相机：第三人称，位置 = 猫后上方（距离 ~2.6m、仰角 ~18°），**lerp 软跟随**，FOV 50°
  （轻微俯视的散步镜头，不是 FPS）

## 6. 性能预算（Three.js 版的硬约束）

- Draw call < 300、三角形 < 400k、无外部资源加载
- 阴影：只允许 1 个 DirectionalLight 投影；点光**不投影**，同屏 PointLight ≤ 4
- InstancedMesh + mergeGeometries 优先于多 mesh
- 移动端（触摸设备）自动降档：pixelRatio ≤ 1.5、bloom 关或减半、阴影 1024

## 7. 验收清单（用户会用这个验收）

1. 不看 UI 时整个世界有统一视觉语言，随便截图像一张 3D 插画
2. 色彩统一（灰绿/米白/暖灰 + 黄昏橙），没有「每个物体各自鲜艳」的拼贴感
3. 无塑料感（roughness 分档 + 材质微差生效），无死黑阴影
4. 黄昏默认场景：天空橙紫渐变、窗户透暖光、贩卖机灯箱亮、长影、薄雾——**这是门面截图**
5. 球面行走流畅（60fps 桌面），能绕星球走一整圈，重力始终指向球心
6. 金色光圈 → 拍照 → 单词卡 → 发音 → 词汇库进度，闭环可用
7. UI 安静：半透明和纸色，视觉重量低于世界
8. 控制台 0 报错；刷新后进度恢复

## 8. 建议实施顺序（视觉优先）

1. 脚手架 + 渲染器（ACES/色彩空间）+ 天空穹顶 + 灯光架 + 四时刻参数表 —— **先让它好看**
2. 星球球体 + 地形色带 + 雾 + Blob shadow 体系
3. 小猫 + 球面行走 + 第三人称相机
4. 建筑族（民居/公寓/车站/便利店/拉面店/咖啡店/邮局/超市/神社）+ 城镇布局
5. 街具族（电线杆/路灯/贩卖机/长椅/邮筒/垃圾桶/招牌/盆栽/晾衣杆/消火栓）
6. 植物（树×3 变体/樱/花坛/草簇）+ 车辆 + 动物
7. 交互闭环（光圈/拍照/单词卡/发音/存档/词汇库）
8. 后处理（Bloom/Vignette/颗粒）+ 移动端降档 + 性能调优

每完成一步对照 §2 验收一次；**发现廉价感时先修基础（色彩/光照/构图），不许加特效遮丑。**
